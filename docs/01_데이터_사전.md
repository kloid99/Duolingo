## 3. 컬럼 간 관계

- `p_recall = session_correct / session_seen` (전 행에서 일치 확인)
- `history_correct <= history_seen` (위반 0건)
- `session_correct <= session_seen`
- `history_seen`과 `history_correct`의 최솟값이 1이므로, 사용자가 처음 보는 단어는 이 데이터에 포함되지 않는다. 각 행은 이미 한 번 이상 본 단어에 대한 기록이다.
- 첫 번째 행의 `delta`가 매우 큰 이유(27,649,635초 ≈ 320일)는 관측 시작 이전의 학습 이력에서 계산된 값이기 때문으로 보인다.

## 4. `lexeme_string` 구조

`표면형/기본형<태그1><태그2>...` 형식이다. 태그는 최소 1개, 최대 14개이며 중앙값은 3개다.

```
lernt/lernen<vblex><pri><p3><sg>
  │      │      │      │    │   └ 수(단수)
  │      │      │      │    └ 인칭(3인칭)
  │      │      │      └ 시제(현재)
  │      │      └ 품사(일반 동사)
  │      └ 기본형(lemma)
  └ 표면형(실제 등장한 형태)
```

`<vblex>`(동사), `<det>`(한정사), `<n>`(명사) 같은 태그의 정확한 의미 목록은 Kaggle 페이지에 상세히 실려 있지 않다. 태그 해석이 필요한 분석에서는 원 논문 문서를 확인해야 한다.

## 5. 이 프로젝트에서의 사용 계획

| 용도 | 사용 컬럼 |
|---|---|
| 성과 지표 | `p_recall`, `session_correct`, `session_seen`. 장기 복습 정답률은 `delta ≥ 1일(86,400초)`인 행으로 계산 |
| 반복 학습 주기 | `delta`, `timestamp` |
| 학습 횟수·누적 경험 | `history_seen`, `history_correct`, `session_seen` |
| 활동량·이탈 판정 | `user_id`, `timestamp`로 산출 (활동일 수, 앞 8일 대비 뒤 4일 학습량) |
| 세그먼트 보조 | `learning_language`, `ui_language` |
| 사용 보류 | `lexeme_id`, `lexeme_string`은 단어 다양성 등 파생 피처에만 제한적으로 사용 |

## 6. 데이터 사전 작성 시 유의사항

- 이 데이터에는 결제, 가입일, 광고 유입 채널, 인구통계 정보가 없다.
- 이탈 라벨이 없다. 프로젝트에서 활동 감소(soft churn)를 직접 정의한다.
- 2013년 데이터이므로 현재 앱의 행동과는 다를 수 있다.
