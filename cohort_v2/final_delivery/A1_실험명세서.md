# A1 재개 후 다음 학습 연결 실험 명세

작성 2026-10-13. 상태: 설계 완료, 실제 배정·노출·효과 검증 미실행. 사업적 최소 효과와 모집 규모는 실행 전 확정할 입력이다.

## 1. 가설과 대상

학습을 재개한 습관 형성형에게 다음 학습일을 정하는 앱 안 안내를 제공하면, 재개 다음 두 UTC 날짜 중 추가 학습 비율이 늘어나는지 검증한다. 역사적 관측 결과는 이 안내의 효과를 보여주지 않는다.

기준 주간은 개시 시점 이전의 완전 UTC 날짜 7개다. 해당 주간 활동 2~3일이고 마지막 학습이 주간 마지막 두 날짜 중 하나인 사용자를 습관 형성형으로 고정한다. 이후 첫 학습 기록 직전에 완전 UTC 날짜 1일 이상 학습 기록이 없는 사용자 A1을 대상으로 한다. 실험당 사용자 배정은 최초 1회다. 기존 계획 안내의 중복 개입 실험에 이미 배정된 사용자는 배정 전에 제외하고 제외 사유를 기록한다. 단말 화면에서 안내를 지원하는 앱 환경 여부도 배정 전 자격 조건으로 고정한다. 이 운영 조건을 추가하면 역사적 기준률과 모집단이 달라질 수 있다.

역사적 A1 4,809명 중 결과를 완전히 관측한 2,880명에서 1,312명(45.6%)이 추가 학습했다. 이를 표본 수 계획의 출발 자료로 사용한다. A 전체 47.6%와 기준집단 전체 반복학습률 24.4%는 다른 지표다. 정확히 2일 비활동에서 복귀를 유도하는 후보 B는 이번 실험에서 시행하지 않는다.

## 2. 안내군과 대조군

| 항목 | 안내군 | 대조군 |
|---|---|---|
| 학습 경험 | 기존 학습 경험 유지, 다음 학습일 계획 카드 추가 | 기존 학습 경험 |
| 최초 노출 시점 | 자격 첫 학습 이벤트를 서버가 확인한 뒤, 학습을 방해하지 않는 다음 화면 | 같은 이벤트에서 배정만 기록 |
| 카드 제목 | 다음 학습을 미리 정해볼까요? | 추가 카드 없음 |
| 카드 본문 | 가능한 날짜를 골라 작은 계획을 남겨요. | 해당 없음 |
| 선택 | 학습일 정하기 / 나중에 | 해당 없음 |
| 선택 후 | 현지 날짜로 다음 학습일을 선택·저장하고 ‘학습일을 정했어요’를 표시 | 해당 없음 |
| 반복 | 사용자당 카드 1회. 선택하지 않거나 닫아도 재노출 없음 | 해당 없음 |

알림 발송을 약속하는 문구는 사용하지 않는다. 이번 제안은 날짜 계획을 남기는 앱 안 안내이며 푸시·메일을 함께 추가하지 않는다. 화면 위치와 실제 컴포넌트 연결은 서비스 구현 단계에 해당한다. 현재 학습 기록은 레슨 완료 로그가 아니므로 ‘레슨 종료 후 노출’로 확정하지 않는다. 날짜 선택은 사용자 현지 표시를 쓰되 연구 결과 판정은 아래 UTC 날짜 기준으로 계산한다.

## 3. 자격 시점과 무작위 배정

1. 고정 기준집단, 앞선 학습 기록, 기존 배정·중복 실험 제외 조건을 확인한다.
2. 첫 후속 `learning_recorded` 이벤트가 들어오면 직전 완전 날짜의 비활동 수가 1일 이상인지 확인한다. 기준 기간 전체의 미래 활동을 자격 판단에 사용하지 않는다.
3. 서버에서 사용자 단위 1:1 무작위 배정한다. 안내 2명·대조 2명의 순서를 무작위로 섞은 블록 4명을 사용하고, 배정·블록 ID·블록 내 위치를 원자적으로 저장한다. 사용자가 재접속하면 기존 배정을 반환한다.
4. 자격 이벤트 시각과 배정 시각의 UTC 날짜를 같게 유지한다. 지연 이벤트가 이미 다른 UTC 날짜로 넘어간 경우 해당 이벤트는 배정 전 기술 사유로 제외하고 새 사건처럼 재활용하지 않는다.
5. 배정 후 실제 카드가 보이지 않았거나 계획을 선택하지 않았어도 안내군에 남긴다. 화면 노출 여부로 분석 대상을 사후 변경하지 않는다.

완전한 블록은 군별 2명이어야 하고 마지막 미완성 블록만 허용한다. 군 이름을 보고 배정 순서를 바꾸지 않는다. 블록 완전성·중복 배정·타군 노출은 결과를 보지 않는 품질 점검 항목이다.

## 4. 주 지표와 분석

- D0: 자격 첫 학습 이벤트의 UTC 날짜. D1·D2: 그 다음 두 완전 UTC 날짜.
- 사용자 결과 Y=1: `[D0+1일 00:00, D0+3일 00:00)`에 유효한 학습 기록 1개 이상. 종료 경계 시각은 포함하지 않는다. D0 당일 추가 세션은 주 지표에 포함하지 않는다.
- 군별 주 지표: Y=1 사용자 수 / 해당 군의 모든 배정 사용자 수. 배정 전 기술 제외자는 분모에 들어오지 않으며, 배정 후 안내 미노출자는 포함한다.
- 주 추정값: 안내군−대조군의 비율 차이(%p). 상대 변화율은 보조 표현이다.
- 주 검정: 한 번의 양측 pooled 두 비율 z 검정, α=0.05. 차이의 개별 95% 구간은 Wilson 기반 Newcombe 구간을 제시한다. 한 개 주 지표이므로 기존 탐색 분석의 Holm 검정군과 합치지 않는다.
- 보조 결과: D1 학습, D2 학습, 양일 학습, 계획 저장률, 카드 닫기 비율. 보조 결과의 유의성으로 주 결과를 대체하지 않는다. 후속 D1~D7의 4일 이상 학습을 탐색적 보조 NSM으로 수집하며, 구간·판정은 아래 보완 계약을 따른다.

UTC 날짜 결과는 고정 48시간 결과와 다르다. 현지 날짜나 48시간으로 바꾸려면 실행 전 명세와 기준률·표본 수를 다시 확정한다. 현지 날짜를 고르는 UI 자체는 주 결과의 날짜 경계를 바꾸지 않는다.

## 5. 가드레일과 데이터 품질

| 항목 | 분모·기간 | 처리 |
|---|---|---|
| 앱 오류 | 배정 후 D0~D2, 배정자 중 오류가 관측된 비율 | 군별 차이와 개별 구간 보고 |
| 학습 화면 진입 실패 | 배정 후 D0~D2, 배정자 중 진입 오류 비율 | 군별 차이·사유 확인 |
| 카드 닫기·사용자 불편 | 안내군 전체 배정자, D0~D2 | 노출·닫기·불편 건수와 비율 기술 |
| 노출 오염 | 대조군 카드 노출 / 대조군 배정자 | 0건을 설계 목표로 두고 발생 시 원인 확인 |
| 배정·로그 무결성 | 사용자 중복, 블록별 수, 사건 ID, UTC 경계·수집 지연 | 결과 판정 전 점검 |

계획용 운영 기준은 앱 오류·화면 진입 실패의 군별 절대 차이 +1%p 이상을 추가 조사 대상으로 두는 것이다. 이는 확증적 비열등성 한계가 아니며 안전성이 입증됐다는 뜻도 아니다. 서비스 기준이 없으므로 실행 전 담당자가 기존 오류율과 허용 폭을 확인해야 한다. 기존 학습을 차단하는 재현 가능한 오류나 대조군에 안내가 노출되는 결함이 확인되면 신규 배정을 중단하고 원인을 수정한다. 결과의 유의성 때문에 임의로 조기 종료하지 않는다.

추적 기간이 끝났어도 수집 지연·장애 때문에 학습 기록 완전성이 확인되지 않으면 Y를 미확인으로 둔다. 해당 사용자를 제외한 비율을 주 ITT 결과로 내지 않는다. 모든 배정자를 남기고 미확인 수와 최악/최선 차이 범위를 보고하며, 보정이 완료될 때까지 주 검정·효과 판정을 유보한다. 두 날짜의 수집이 완전하고 유효 학습 기록이 없을 때만 Y=0이다.

## 6. 표본 수와 기간

초기 작성 가정은 최소 탐지 개선 폭 +3%p, 검정력 80%, 양측 α=0.05, 1:1 배정이다. 45.6%→48.6% 가정에서 군별 4,346명, 총 8,692명이 필요하다. 전체 블록 4명에 맞춰 반올림했다. +3%p는 아직 사업적 최소 의미 효과로 합의된 값이 아니며 +2·5%p, 검정력 90% 시나리오도 제공한다.

모집은 최소 14개 완전 UTC 날짜를 포함하고, 목표 표본을 채운 뒤 현재 블록을 완료해 종료한다. 계획용 최대 모집 기간은 28일이다. 28일에 목표를 못 채우면 표본 미달로 종료·보고하며 분석 도중 MDE를 바꾸거나 다른 세그먼트를 추가하지 않는다. 최신 서비스의 자격 모수와 신규 자격 유입량이 있어야 이 계획의 실행 가능성을 확정할 수 있다.

| 신규 자격 인원/일 가정 | 목표까지 필요한 모집일 | 28일 내 목표 가능 | 모집·추적·지연 대기 후 결과 시점 |
|---:|---:|---|---:|
| 100 | 87 | 불가 | 최대 32일, 표본 미달 |
| 500 | 18 | 가능 가정 | 22일 |
| 1,000 | 최소 기간 적용 14 | 가능 가정 | 18일 |

기간에는 모집 종료 뒤 주 결과 날짜 2일과 수집 지연 대기 2일을 더했다. 단, 14~28일 종료일까지 배정한 추가 사용자도 전체 분석에 포함하므로 최종 표본이 계획 최소치보다 많을 수 있다. 이 표는 가정별 계산이며 실제 신규 유입량·개시일·고정 기준집단의 충분한 규모는 현재 미확인이다.

## 7. 종료·판정과 실행 조건

결과는 목표 또는 기간 상한에 도달하고, 마지막 배정자의 D2가 끝나며, 48시간 지연 대기가 지난 뒤 한 번 확인한다. 데이터 품질 문제나 미확인 결과가 남으면 먼저 원인을 해결한다.

- p<0.05이며 안내군 비율이 높으면 통계적 개선 근거로 기록한다.
- 추정 개선 폭이 작성 가정 +3%p 이상이고 가드레일 악화가 없으면 제한적 후속 확대를 검토한다. +3%p 이상의 효과가 통계적으로 입증됐다는 표현은 차이 구간 하한도 +3%p를 넘는 경우에만 사용할 수 있다.
- 주 검정이 유의하지 않으면 근거 부족으로 보고하며 효과 0·동등성을 주장하지 않는다.
- 음의 차이, 운영 결함 또는 표본 미달은 각각 보고한다. 보조 지표가 좋아도 주 결과를 성공으로 바꾸지 않는다.

실행에 필요한 항목: 최신 고정 기준집단과 신규 자격 인원, 이벤트·배정·노출 로그 연결, 앱 카드 구현, 사업적 MDE·운영 가드레일 확인, 개시일. 설계·측정·표본 계산은 완료했으며 실제 서비스 배정·노출은 시행하지 않았다.

방법 참고: [statsmodels의 두 독립 비율 검정력 정의](https://www.statsmodels.org/stable/generated/statsmodels.stats.proportion.power_proportions_2indep.html). 영가설의 통합 분산과 대립가설의 각 군 분산을 사용하는 정규근사로 계산했다.


## 2026-10-13 검토 보완: 적용 범위와 실행 차단 조건

공개 파일의 비활동은 **유효 단어 lesson/practice 기록이 없는 완전 UTC 날짜**다. 앱 미사용·모든 학습 부재·영구 이탈을 뜻하지 않는다. 원본의 최초 단어 노출 포함 여부와 모든 세션 coverage는 검증되지 않았다. 현재 주간 NSM 9,834명도 관측 기록 기준 지표다.

A1 자격은 비활동 1일 이상을 유지한다. 45.6%는 3/8·9 재개 및 비활동 1~2일의 조건부 비율이다. 전체 후보 4,809명 중 1,929명(40.1%)은 완전 D1·D2가 없다. 날짜별 비율은 3/8 549/1,307=42.0%, 3/9 763/1,573=48.5%; 3/10·11은 미확인이다. 비활동 3일 이상 결과를 0으로 채우거나 짧은 비활동으로 자격을 사후 축소하지 않는다.

실제 서비스의 고정 주간 대상에서 **카드 없는 사전 관측 기간**을 먼저 확보한다. 모집 예정 14~28일의 날짜별 신규 고유 자격 수·비활동 1일/2일/3일 이상·지원 앱 구성·자격 모수와 D1·D2 기준률을 측정한다. 각 층의 n/K/coverage/미확인 수를 보고하고, 예정 모집 구성으로 전체 기준률을 다시 산출한다. 모든 결과는 D3+지연 대기 후 확정한다. 표본 부족·coverage 미확인 층이 있으면 모집 기간/범위를 사전에 재설계하고 계획을 다시 생성한다. 43.7~47.4% 구간에 따른 총 표본 8,640~8,716명은 기존 표본의 통계적 민감도이며 모집단 이동 오차를 해결하지 않는다.

설정의 launch_gates가 모두 true이고 실제 유입량·개시일이 있어야 실행 검토가 가능하다. 사업적 MDE +3%p, 가드레일 조사 +1%p, 모집 14~28일은 승인 전 작성 가정이다. 현재 gate는 null로 두며 자동 실행·효과·안전성 확인으로 간주하지 않는다. `validate_experiment_config.py --require-ready`는 미확인 입력이 남으면 실패한다.

## 후속 7일 NSM과 날짜 선택

보조 NSM은 모든 배정자를 분모로 D1~D7의 유효 서비스 학습 날짜가 4일 이상인지 측정한다. 구간은 [D1 00:00,D8 00:00), 판정은 D8+48시간 이후다. 수집 미확인은 None으로 유지하고 군별 K/N~(K+M)/N을 보고한다. D0는 제외하며 같은 날짜의 여러 사건은 1일이다. 주 지표의 유의성만으로 NSM 개선을 선언하지 않는다. 마지막 배정 이후 보조 결과에는 7일 추적+2일 대기가 필요하다.

UI에서는 D1·D2 UTC 구간과 교집합이 있는 사용자 현지 날짜만 제공한다. 각 날짜의 허용 시각 구간을 서버에서 계산해 보존하며, 현지 날짜 일부가 측정 구간 밖일 수 있음을 날짜 표시/선택 가능 시간으로 안내한다. 미래의 임의 날짜는 선택할 수 없다. 사용자의 timezone을 저장하고 DST도 시간대 데이터로 변환한다. 제목/본문은 기존 쉬운 문구를 유지한다. UI와 주 측정 기간의 일치는 출시 전 사용성·경계 테스트 gate다.
