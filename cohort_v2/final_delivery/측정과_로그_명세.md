# A1 측정과 로그 명세

2026-10-13. `experiment_config.json`과 A1 실험 명세에 대응한다. 아래는 신규 서비스 구현에 필요한 계약이며 현재 원본에서 배정·노출·계획 저장을 추정해 만들지 않는다.

## 필수 테이블

| 테이블 | 필수 필드 | 유일성·조건 |
|---|---|---|
| cohort_snapshot | snapshot_id, user_id, cohort_asof_utc, active_days, last_learning_at_utc, segment, rule_version | snapshot_id+user_id 고유. 기준 주간 완료 후 고정 |
| experiment_assignments | assignment_id, experiment_id, user_id, variant, eligibility_event_id, eligibility_at_utc, assigned_at_utc, snapshot_id, block_id, block_position | 실험+사용자 고유, assignment_id 고유, variant=control/treatment |
| learning_events | event_id, user_id, occurred_at_utc, received_at_utc, valid | event_id 고유, timezone 필수. 레슨 완료 여부를 대신하지 않음 |
| plan_card_events | event_id, assignment_id, occurred_at_utc, event_type, selected_local_date, display_timezone | event_type=shown/dismissed/plan_saved. plan_saved만 선택 날짜 필수 |
| app_quality_events | event_id, assignment_id, occurred_at_utc, event_type, error_code | 앱 오류·학습 진입 오류·불편 사건. 비발생은 수집 완전성과 함께 판단 |
| daily_log_coverage | date_utc, version, complete, checked_at_utc, incident_id | UTC 날짜+양의 정수 version 고유. 버전 증가 시 확인 시각 단조 증가. ‘그 날짜 학습 없음’과 ‘수집 장애’를 구분 |

모든 사건 시각은 시간대가 포함된 UTC ISO 8601로 저장하고 수집 시각과 분리한다. 사용자 식별자는 연결 키다. 기간 내 첫 학습을 자격으로 확인하는 이력은 후보 배정 이전까지로 한정한다. 기준집단 조건·지원 앱·중복 실험 제외 등의 사유는 `eligibility_decisions`에서 decision_id, user_id, experiment_id, evaluated_at_utc, eligible, reason, snapshot_id로 보존한다.

## 배정과 관측의 연결

`experiment_assignments`의 모든 배정자가 분석의 출발점이다. 카드 사건이나 학습 사건의 존재로 배정자를 먼저 거르지 않는다. 안내 미노출·계획 미저장자는 해당 군에 유지한다. learning_events는 user_id, 안내·품질 사건은 assignment_id로 연결한다. 배정 사용자와 타군 카드의 연결은 품질 오류다.

UTC 날짜 D0를 eligibility_at_utc에서 계산한다. 유효 학습 사건의 발생 시각이 D1 00:00 이상, D3 00:00 미만이고 수집 시각이 데이터 동결 시각 이하인지 확인한다. event_id 중복은 내용이 완전히 같을 때만 한 사건으로 처리하며 서로 다른 내용이면 입력 오류로 중단한다. 실험+사용자의 중복 배정도 자동으로 한 행을 골라 숨기지 않는다.

## 결과의 상태

| 상태 | 조건 | 주 결과 처리 |
|---|---|---|
| 추적 중 | 데이터 동결 시각이 D3 00:00+48시간 이전 | 미확인, 해당 사용자 유지 |
| 수집 미확인 | D1·D2 coverage가 완전하지 않음 | 미확인, 학습 없음으로 바꾸지 않음 |
| 추가 학습 | 지연 대기 종료·동결 당시 coverage 완전, 유효 사건≥1 | Y=1 |
| 추가 학습 없음 | 지연 대기 종료·동결 당시 coverage 완전, 유효 사건=0 | Y=0 |

실험 전체에서 미확인 결과가 있으면 군별 모든 배정자 수 N, 확인된 성공 K, 미확인 M을 보고한다. 비율 범위는 K/N~(K+M)/N, 안내−대조 차이 범위는 `K_T/N_T−(K_C+M_C)/N_C`부터 `(K_T+M_T)/N_T−K_C/N_C`다. 이 범위는 신뢰구간이 아니라 미확인 결과의 경계다. 주 검정은 모든 결과가 확인된 뒤에만 계산한다.

`measurement_reference.py`는 위 주 지표의 참조 계산이다. JSON으로 assignments, learning_events, coverage를 받고 각 사용자 결과와 군별 분모·미확인 범위를 반환한다. 블록 배정기나 앱 노출 코드를 구현한 것은 아니다. `verify_measurement_reference.py`에서 UTC 경계·안내 미노출·수집 장애·중복·추적 미완료를 합성 입력으로 검증한다. 합성 검증을 실제 실험 결과로 사용하지 않는다.

## 실행 전 점검

모든 필드와 연결 키, 기준집단 고정 시각, 중복 없는 배정, 완전 블록의 2:2 수, 안내군만 카드 노출, 사용자당 1회, UTC 결과 경계, 사건 수집 지연과 coverage 판정을 점검한다. 원본 학습 기록은 실제 첫 이벤트 시각을 제공하지만 배정·화면 노출·계획 저장·앱 오류 로그는 제공하지 않는다. 신규 시스템의 연결·점검 결과는 현재 미확인이다.


## 강화된 학습 사건·coverage 계약

서비스 learning_recorded는 최초/재노출 단어와 무관하게 완료된 유효 학습 세션을 서버가 확인한 사건이다. session_id, event_id, user_id, session_type, occurred_at_utc, received_at_utc, schema_version을 보존한다. 중복 전송은 event_id로 제거하고 테스트/자동화/무효 세션은 valid=false 및 사유를 기록한다. 단순 앱 열기나 카드 선택은 학습 사건이 아니다. 단어 로그와 세션 계약은 같다고 가정하지 않는다.

실제 서비스 기준 주간에서 전체 학습 세션의 사용자-UTC날짜 집합과 공개 자료 방식의 단어 기록 집합을 비교해 일치/세션만/단어만의 수와 이유를 기록한다. 최초 학습·지원 앱·언어별 누락을 검사하고, 이 검증과 수집 완전성 점검이 통과되기 전 서비스 NSM으로 적용하지 않는다. 실제 비교 수치는 현재 없다.

coverage는 해당 UTC 날짜가 끝난 후 checked_at_utc를 기록한다. 동일 날짜 버전 중 동결 시각 이하 최신 버전만 사용한다. 미래 버전은 사용하지 않는다. 이전 true를 최신 false가 번복하면 미확인이다. 시각·버전 누락, 중복 버전, 역행 확인 시각은 입력 오류로 중단한다. 최소 48시간 대기와 coverage 둘 다 충족해야 0/1을 확정한다. 동결 이후 도착 사건은 그 동결 결과에서 제외한다. coverage의 완전성 판정이 나중에 잘못으로 확인되면 새 버전과 새 동결 분석을 남기고 과거 결과를 덮어쓰지 않는다.

measurement_reference.evaluate의 data_lateness_allowance_days는 기본 2일이며 실행 설정과 같아야 한다. D1·D2 주 결과와 D1~D7 4일 이상 보조 NSM을 모두 반환한다. 보조 NSM에도 모든 배정자·동일 coverage 버전·지연 대기를 적용한다. 주 결과는 D3+2일, 보조 결과는 D8+2일 전까지 각각 미확인이다.
