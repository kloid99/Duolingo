검토일 2026-10-13. 범위: v3 코호트·세그먼트, 후속 분석, A1 대상, 최종 보고서, 실험·측정 코드와 검증 방식. 기존 산출물·모형을 수정하지 않고 새 진단과 합성 반례를 별도 저장했다.

## R01. 측정 코드가 실험 명세의 대기 시간을 강제하지 않는다

[측정 참조 코드](C:/Users/USER/OneDrive/마케팅/cohort_v2/final_delivery/measurement_reference.py:41)는 `freeze >= D3 00:00`과 두 날짜의 complete 값만 확인한다. 실험 명세는 D2가 끝난 뒤 48시간 수집 지연 대기를 요구한다. 현재 함수는 그 대기를 계산하지 않는다.

합성 입력에서 D0=3/8, D1=3/9, D2=3/10으로 두고 3/11 00:00에 동결하면, 학습 기록이 없는 사용자를 완전 관측 Y=0으로 반환했다. 명세를 적용하면 최소 3/13 00:00까지는 최종 판정을 기다려야 한다.

또한 [coverage 처리](C:/Users/USER/OneDrive/마케팅/cohort_v2/final_delivery/measurement_reference.py:19)는 `checked_at_utc`를 사용하지 않는다. coverage 확인 시각이 3/15인데 동결 시각을 3/13으로 준 반례도 complete를 받아 Y=0을 반환했다. 동결 당시 알 수 없던 완전성 판정을 받아들이는 문제다. 두 반례는 `review_diagnostics.json`에 저장했다.

보완 조건: 지연 대기를 명시적 매개변수 또는 실험 설정에서 읽고, `freeze >= outcome_end + allowance`를 확인한다. coverage 판정의 시각·버전을 검증하고 동결 시점 이후 판정은 미확인으로 처리한다. 수정 후 정확한 경계 직전/직후, 과거·미래 coverage, 늦게 도착한 사건을 함께 검증한다. 현재 함수는 주 지표 참조 계산이며 배정기·앱 구현이 아니지만, 실제 결과 계산에 연결하기 전 이 누락은 해결해야 한다.

## R02. 45.6%의 적용 범위가 실험 모집 범위보다 좁다

| A1 첫 후속 학습 날짜 | 전체 후보 | D1·D2 완전 관측 | 추가 학습 | 관측률 |
|---|---:|---:|---:|---:|
| 3/8 | 1,307 | 1,307 | 549 | 42.0% |
| 3/9 | 1,573 | 1,573 | 763 | 48.5% |
| 3/10 | 971 | 0 | 미확인 | 미확인 |
| 3/11 | 958 | 0 | 미확인 | 미확인 |
| 합계 | 4,809 | 2,880 | 1,312 | 45.6% |

완전 관측자는 전체 A1 후보의 **59.9%**, 미완전 관측자는 **40.1%**다. 완전 관측 표본의 직전 비활동 기간은 1~2일뿐이다. 미완전 관측 표본에는 2~4일 비활동자가 포함되고, 현재 실험 자격은 비활동 1일 이상으로 상한이 없어서 14~28일 모집 중 더 긴 비활동 뒤 재개자도 포함할 수 있다.

완전 관측 표본의 평균 직전 비활동은 1.21일, 미완전 관측 표본은 2.91일이다. 날짜별 42.0%와 48.5% 차이는 날짜·요일·대상 구성의 복합 차이일 수 있으며 날짜의 인과 효과로 해석하지 않는다.

늦은 재개자를 0으로 넣지 않은 기존 처리는 적절하다. 다만 그 결과로 얻은 45.6%는 초기 재개자의 조건부 관측률이다. Wilson 구간 43.7~47.4%는 이 표본의 비율 불확실성을 나타내며 다른 모집단으로 옮길 때의 오차까지 포함하지 않는다.

보완 조건: 45.6%를 계획 참고값으로 유지하되 대상의 재개 지연·비활동 기간 분포를 새 서비스와 비교한다. 사업적으로 동일한 짧은 비활동 재개자를 대상으로 정할지, 더 긴 비활동자를 포함해 기준률을 다시 산출할지 실행 전에 결정한다. 관측이 가능한 사람만 남기기 위해 사후에 자격을 바꾸지 않는다. 현재 파일만으로 3일 이상 비활동 재개자의 D1·D2 비율을 복원할 수 없다.

## R03. ‘학습 기록 없음’의 의미를 데이터 범위에 한정해야 한다

원 데이터는 사용자-단어별 lesson/practice 이력이다. 원 논문은 이를 기억·회상 모델 연구에 사용한 로그로 설명한다. [원 논문 §4.1](https://aclanthology.org/P16-1174.pdf), [공식 컬럼 설명](https://github.com/duolingo/halflife-regression).

로컬 [데이터 사전](C:/Users/USER/OneDrive/마케팅/docs/01_데이터_사전.md)은 history_seen 최솟값이 1이므로 최초 단어 노출 행이 없다고 기록한다. 이 사실만으로 사용자 세션이 실제로 누락됐다고 단정할 수는 없다. 그러나 모든 학습 세션·서비스 활동이 이 파일에 빠짐없이 나타난다는 coverage 검증도 없다.

따라서 현재 비활동은 ‘해당 공개 파일에서 유효 학습 기록이 없는 완전 UTC 날짜’로 해석해야 한다. 실제 앱 미사용, 모든 학습의 부재, 영구 이탈로 확대하지 않는다. NSM 9,834명과 6개 집단도 관측된 기록 범위에서의 지표다. 현재 날짜를 완전 날짜로 골랐다는 것은 기간 경계 처리이며 이벤트 coverage 전수 검증과 다르다.

보완 조건: 지표 정의와 보고서의 관측 범위를 분명하게 연결한다. 실제 서비스에 적용할 때는 단어 재노출 이력 대신 어떤 학습 세션 이벤트를 사용하며 최초 학습을 포함하는지 정하고, 두 이벤트 체계의 사용자-날짜 일치율을 확인한다. 원 논문의 모집 범위 설명만으로 앱의 모든 활동과 동일하다고 주장하지 않는다.

## R04. 선택 표본과 강건성 검토를 보강해야 한다

같은 습관 형성형 14,583명 안에서도 분석 가능 조건에 따라 학습 행동이 달랐다.

| 분석 | 포함 인원 | 포함 비율 | 포함자의 추적 반복학습률 | 제외자의 반복학습률 |
|---|---:|---:|---:|---:|
| 세션 간격 변동성 | 10,633 | 72.9% | 27.2% | 17.1% |
| 전체 정답률 변화 | 4,653 | 31.9% | 25.8% | 23.8% |
| 같은 단어 개선 | 8,354 | 57.3% | 27.2% | 20.6% |

표는 기술 통계다. 포함 조건이 미래 반복학습 차이를 일으킨다는 뜻이 아니다. 이미 보고서에 대상 수와 다른 표본의 OR 비교 금지가 있지만, 이 프로필을 더하면 왜 전체 집단으로 확대할 수 없는지 명확해진다. 비유의 결과를 제외자에게까지 적용하거나 전체 집단의 무관함으로 해석하지 않는다.

기존 [품질 점검표](C:/Users/USER/OneDrive/마케팅/docs/02_데이터_품질_점검표.md:45)는 누적 노출 history_seen>1,000인 사용자 104명의 포함/제외 비교를 예정했다. 현재 v3의 분석 코드·산출물에서 그 비교 결과를 찾지 못했다. 해당 사용자가 자동화 계정이라는 뜻은 아니며, 기준에 따른 영향 점검의 완료 근거가 부족하다는 뜻이다.

직접 간격 모형의 노출 가중에서 상위 1% 사용자 231명이 총 가중의 8.9%를 차지했다. 가장 큰 한 사용자 비중은 0.154%로, 한 사용자가 결과를 지배한다고 확인된 것은 아니다. 가중 방식에 따른 추정 대상 차이는 기존에 올바르게 설명했다. 추가 영향 분석 없이 ‘헤비 사용자 탓’이라고 결론 내리지 않는다.

보완 조건: 기존 품질표 기준의 포함/제외 민감도, 상위 가중 사용자 제외 또는 영향력 진단, 분석 대상의 언어·관측 시점 구성과 모형 형태를 확인한다. 새 임계값을 계속 바꿔 유의한 결과를 찾지 않는다. 시간 외 검증을 하려면 현재 한 개의 완전 7일 기준+4일 추적 창보다 긴 데이터가 필요하다. 가입·채널·동기 정보가 없다는 한계는 계속 남는다.

## R05. 검증이 보고서의 의미 연결까지 확인하지는 못한다

[보고서 검증 코드](C:/Users/USER/OneDrive/마케팅/cohort_v2/final_delivery/verify_final_delivery.py:46)는 53개 표시값이 보고서 문자열 어딘가에 존재하는지 확인한다. 원천 값의 계산 대조와 저장 엑셀 대조는 별도 수행됐지만, 이 보고서 검사는 값이 맞는 집단·지표·기간에 붙었는지 검사하지 않는다.

실제 보고서는 수정하지 않고 메모리 안에서 꾸준형과 최근 단발형의 표 라벨을 교환했다. 숫자는 그대로이므로 이 표시값 존재 검사는 여전히 통과했다. 이 반례는 현재 보고서가 틀렸다는 증거가 아니라 자동 검증의 사각지대를 보여준다.

또한 최종 검증은 현재 experiment_config.json을 표본 계산에 기록한 입력 해시와 비교하지 않고, sample_size_results.json의 저장된 설정을 기준으로 계산한다. 입력 설정을 바꾼 뒤 재생성을 빠뜨린 경우를 검출하는 의존성 검사가 필요하다. 현재 설정과 저장 계획이 불일치한다고 이번에 발견한 것은 아니다.

최종 검증 때 manifest를 새로 쓰는 방식도 보존 감사와 재생성 기록을 구분해야 한다. 기존 분석의 80개 파일 해시 대조는 수행됐지만, 최신 패키지에 대해 이전 manifest의 해시를 비교하는 읽기 전용 감사와 새 빌드의 manifest 생성은 다른 기능이다.

보완 조건: 보고서 표의 집단·metric_id·기간·분모·분자·단위를 구조적으로 대조한다. 라벨 교환·단위 변경·MDE 변경 후 미재생성 같은 부정 테스트를 추가한다. Verify는 현재 입력과 기존 manifest를 확인하고 별도 감사 기록을 남기며, Build에서만 새 manifest를 작성한다.

## R06. NSM과 사업적 실행 조건은 아직 검증되지 않았다

D1·D2 중 하루 추가 학습은 합리적인 단기 실험 지표지만 후속 7일 중 4일 학습을 의미하지 않는다. 이번 데이터는 추적 4일이라 그 연결을 검증할 수 없다. 이 부분은 이미 보고서에 한계로 기록돼 있으며 계산 오류가 아니다.

새 데이터에서는 후속 7일의 기준 시작일·종료일을 정하고 NSM 또는 7일 학습일 수를 보조 결과로 수집해야 한다. 단기 주 지표의 유의성만으로 NSM 개선을 선언하지 않는다. 앱의 계획 안내가 끊김을 해결하는 기전은 아직 가설이며 중단 사유 조사나 파일럿 사용성 확인이 도움이 된다.

+3%p MDE, 모집 최소 14일·최대 28일, 가드레일 +1%p 조사 기준은 작성 가정이다. 산식은 재현됐지만 효과의 사업 가치·운영 허용 폭·실제 자격 모수는 미확인이다. 고정 기준집단에서 새 자격 인원이 계속 생기는 방식이므로 일별 일정 유입을 실제 모집 규모로 확정할 수 없다. 출시 전에 이 입력을 확인해야 한다.

## 작은 실행 명세 보완

- 날짜 계획 UI는 현지 날짜를 사용하지만 선택 가능한 날짜 범위가 정해지지 않았다. 멀리 떨어진 날짜를 선택하도록 허용한다면 D1·D2 주 지표와 유도 행동이 어긋날 수 있다. 선택 범위와 UTC 결과 기간의 관계를 명시한다.
- 표본 수 엑셀의 개별 입력 검사는 양수·소수 범위 위주다. 최대 모집일≥최소 모집일 같은 칸 간 조건은 검사하지 않는다. 기본값 14/28은 일치하지만 최대 7일 입력도 양수 조건을 통과할 수 있으므로 상한 적용 결과를 7일로 계산한다. 실행용 인계 전에 입력 관계 검증을 보강한다.

## 다음 작업 순서와 완료 기준

1. **R01 측정 코드 보완:** 대기·coverage 시점·버전을 반영하고 이번 두 반례 및 기존 14개 경계 사례를 통과시킨다.
2. **R03 정의·R02 적용 범위 보강:** 기록 기반 비활동을 명시하고 A1 날짜/비활동 프로필을 보고서에 연결한다. 새 서비스 대상과 45.6%의 모집단 일치 여부를 확인한다.
3. **R05 검증 보강:** 보고서 라벨·단위·기간과 최신 입력 해시를 검사하고, 잘못된 입력/라벨은 실패하도록 한다.
4. **R04 강건성:** 기존 104명 기준의 영향 점검 등 사전 정한 민감도만 수행하고 결과 방향·크기·표본을 함께 보고한다.
5. **R06 실행 판단:** 충분한 후속 기간과 실제 로그, 모집 규모, 사업적 MDE·가드레일을 확보한 뒤 실험을 시행한다.

현재 데이터로 가능한 작업은 측정 참조·검증 코드 보강, 관측 범위 문구와 선택 표본 프로필, 추가 영향 진단이다. 늦은 재개자의 완전 D1·D2 결과, 여러 기준 주간의 복제, 후속 7일 NSM과 실제 안내 효과에는 추가 데이터가 필요하다.

## 유지할 부분과 검토 범위

고정 기준집단 유지, 미관측을 0으로 채우지 않은 처리, 단어 delta와 사용자 세션 간격 구분, 같은 단어 지표 별도 재현, 사용자 군집 표준오차, 개별 신뢰구간·검정군 구분, 대상과 이후 결과 분리는 유지할 만하다. 여러 모형의 수치 교차검증은 계산 재현성에 도움이 되지만 표본 적용 가능성·인과성·운영 구현까지 검증하지는 않는다.

이번에는 주요 코드·결과·문서 검토와 새 진단 집계를 수행했다. 전체 원본의 품질 검사를 다시 반복하거나 모든 회귀를 재적합하지 않았다. 기존 결과를 틀린 값으로 교정할 근거가 확인된 것은 아니다. 실험 측정 반례와 보고서 검증 반례는 합성 입력/메모리 안 변경이며 실제 배정이나 기존 파일 변경이 아니다.
